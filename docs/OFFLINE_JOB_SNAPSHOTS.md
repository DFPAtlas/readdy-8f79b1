# Read-only offline job snapshots

A signed-in worker with an active company membership and saved assignment to a non-archived job can save its summary and their own assigned tasks from Mobile Jobs or the job Team tab. A read-only RPC derives the account from auth.uid() and exports only company name, job reference/name/status/progress/target date and that account's task title/details/status/due date. Other people's tasks, contacts, financial fields, access notes, attachments, credentials and signed URLs are excluded. A response above 1,000 tasks or 3 MB fails rather than producing a partial pack.

Downloads first prepare the public app shell and same-origin build JS/CSS through the service worker. A failed preparation blocks the download confirmation. Only static same-origin `/assets/` files are cached; API/auth/storage data is not put in Cache Storage. The worker can use the cached public shell for `/mobile/offline-jobs` navigation when offline. Other app routes retain their guards/fallbacks. The fallback page no longer promises automatic syncing.

The saved-copy reader is behind AuthGuard but separate from the network-dependent OrgGuard. It lists only packs for the current signed-in account and lets the user select their saved companies. It does not grant live company access or bypass guards on other routes. A retained valid sign-in and cached app assets are required; expired authentication requires reconnecting to sign in. This is not an offline sign-in mechanism.

Snapshots expire 24 hours after the server timestamp. Expiry hides contents and cleanup removes expired supported copies when the reader checks them; the device cannot run cleanup while the app is closed. Expiry uses the device clock and is not an adversary-resistant revocation mechanism. When the network is available the reader revalidates the saved job assignment on open, refresh, returning to the tab and reconnect. A confirmed access denial removes the corresponding copy. A network failure may show an unexpired local copy labelled as not live-validated; other server/check errors hide content pending retry. Immediate remote revocation cannot be enforced offline. The reader's expiry timer clears visible data before reloading.

Each download is bound to user/company/job and has a local revision. Account/scope changes abort pending work, including a pending IndexedDB save. Local saves are confirmed only after transaction commit and readback. Conditional cleanup cannot delete a newer download that replaced the same key. At most 20 supported copies per account can be saved; replacing a job's copy is allowed. Legacy pack contents are not displayed, but the account can remove its older records. Data stays in browser storage until removed or cleaned up; switching accounts hides it, and signing out does not itself delete it. Use a trusted device. Browser storage is not application-encrypted and can be cleared or evicted by the browser.

No offline edits, task/attendance updates, upload execution, conflict resolution or sync are included. Saved statuses are historical, not current instructions or proof of present assignment. A snapshot is an export at read time, not a frozen transactional history across future changes.

## Rollout

After review and merge, apply `20261031110649_offline_job_snapshots.sql` before publishing the frontend and service worker in Readdy. No new tables, Edge Functions, secrets or cron jobs are needed. The migration is a read-only export RPC and has not been applied during implementation. No production snapshots were downloaded. The service worker version changes to `v2.18.2`; if an older worker cannot prepare the reader, refresh and retry after the new worker activates.

## Validation

Database tests execute the migration and reject unassigned owners, foreign company/job scopes, removed membership, archived jobs and anonymous/service-role RPC access. They verify the exported field allowlist, own-task filtering, exact lifetime and oversized task rejection without truncation. Service tests check scope, expiry, offline fallback, confirmed revocation versus transient errors, aborts and foreign-account removal denial. IndexedDB tests cover an abort after save request success and version-aware cleanup. Worker tests check public/static-only warming, missing-asset failure and cached-shell fallback. Full Node tests, TypeScript, zero-warning lint and production build run before review. Real device/browser offline lifecycle testing has not been performed; existing Vite warnings remain.
